# 动效短片模块（motion）

**适用**：用代码/时间轴逐帧渲染，卡音乐节拍剪成 mp4 的短片（标题片头、课程演示、数据动画、产品动效）。
**不适用**：单张概念图（走七段式）、需要真实三维空间与骨骼动画的项目（走 Blender/C4D）、PPT 页面内排版。

**来源说明**：方法论参考 `KRYPT-123/kiro-motion-studio`（139★，**无 LICENSE 文件，版权默认保留**）。本文件只吸收通用做法，未复制其代码、未引用其示例素材与品牌。以下均为工程经验，不是任何工具的官方规范。

---

## 一、每个镜头至少四层

| 层 | 作用 | 写/做的时候注意 |
|---|---|---|
| 背景 | 定空间与基调，占画面最大面积，决定整体明暗 | 运动要最弱；换背景不能牵动主体 |
| 主体 | 唯一视觉中心，动作幅度最大 | 位置、缩放、旋转只在这一层算 |
| 装饰 | 光斑、粒子、线条、纹理流动，负责"活" | 数量可控，不能比主体更抢眼 |
| 前景 | 压暗或虚化的近景元素，制造纵深 | 可以动得比主体快，但不能遮住主体关键部位 |
| 后期 | 调色、颗粒、暗角、统一质感 | 放在最后统一加，不要逐层各调一套 |

**硬要求**：一层一个容器/图层/组，改一层不牵动其他层。四层混在一个画布里，改一处全崩。

---

## 二、先分析音乐，再定镜头时长

顺序不能反：**先听节拍 → 算每拍帧数 → 再决定镜头切在哪**。先做画面再硬套音乐，一定会出现"卡不上"。

| 步骤 | 做法 |
|---|---|
| 1 取 BPM | 用音频工具读出 BPM，或数 8 小节总时长反推 |
| 2 算拍长 | 一拍秒数 = 60 / BPM；一拍帧数 = 帧率 × 60 / BPM |
| 3 标重音 | 找出重音落在第几拍，重音位置就是候选切点 |
| 4 分段落 | 前奏 / 主段 / 高潮 / 收尾，各段节奏不同 |
| 5 定镜头 | 快切段 4~8 拍一个镜头；慢段 16~32 拍；整片开头 2~4 拍给一个"钩子"镜头 |

**卡点规则**：切点落在重音后 1~2 帧内，不要切在音尾；宁可晚 1 帧，不要早 1 帧。
**时间轴单位**：统一用"拍"或"帧"排，不要一会儿秒一会儿毫秒，BPM 一改就会全错。

## 三、七条常见注意点（通用教训）

1. **中文字体缺字**：渲染环境常常没装中文字体，汉字渲染成方框。打包时把字体文件一起带上，渲染前检测字体族是否存在；标题优先用常见字体（思源黑体 / Noto Sans SC）。
2. **数值算出 NaN**：时长、帧数、插值一旦出现 NaN 或 Infinity，轻则单帧黑屏，重则整段渲染失败。所有时长在入口处做"非零、非负、有限"校验，单位统一。
3. **原生依赖打包**：带平台二进制的音视频/图像库，换机器或打包后常找不到。锁定版本、记录运行环境；能换纯脚本实现就换。
4. **坐标系不统一**：不同层用不同基准尺寸，缩放后整体错位。全片只用一个画布坐标系，位置用百分比。
5. **资源路径写死**：绝对路径本机能跑、换机就断。全部相对路径，素材集中一个目录，文件名不用中文和空格。
6. **一次渲染整片**：慢且难排错。先出低分辨率预览 + 抽单帧截图检查构图，确认后再全量渲染。
7. **音频与画面不等长**：音频比画面长会出现空白尾巴，短则被截断。先取音频真实时长，再排时间轴。

---

## 四、适用边界（说清楚，避免误用）

- 这套是**程序化渲染 + 卡点剪辑出 mp4**：画面由代码/时间轴画出来，最后合成视频文件。
- **不能替代 3D 建模管线**：要真实三维空间、角色绑定、骨骼动画，走 Blender / C4D / Maya，不要用二维层去硬凑。
- **不进 PPT**：产物是视频，PPT 里只能嵌入播放，不能在页面内编辑；要可编辑的页面，走 PPT 模块。
- **不适合精细单张插画**：需要手绘质感、材质细节的单图，走图像生成，不走逐帧渲染。

---

## 五、动效短片自检 6 条

1. 四层是否分开？改背景会不会动到主体？
2. 镜头时长是否为"拍的整数倍"，切点是否落在重音后 1~2 帧？
3. 快切段是否落在 4~8 拍区间？
4. 所有时长是否做过非零/有限校验？
5. 字体、素材、依赖是否随包带走、路径是否相对？
6. 是否先出过预览与单帧检查，再全量渲染？
